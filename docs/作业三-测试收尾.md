# 作业三：测试收尾——验收测试与项目总结

## 作业说明

项目主体功能已经完成。本作业用于补齐测试、问题修复、复测验收和项目总结材料，证明当前版本可以运行，核心流程可用，内容配置符合规范。

## 作业目标

对项目当前版本进行完整验收，形成可复现的测试指南、测试记录、缺陷闭环和团队复盘材料。

## 作业内容

1. 编写测试环境和启动说明，记录依赖版本、配置方法和运行命令。
2. 设计并执行核心流程测试，至少覆盖：
   - 开始游戏；
   - 角色或宗门选择；
   - 事件推进；
   - 玩家自由输入；
   - 玩家状态变化；
   - 存档与读档；
   - 异常处理或 Agent 降级机制。
3. 执行内容配置校验，并保存命令和结果：

   ```bash
   python content/tools/validate_content.py --path content --verbose
   ```

4. 汇总测试中发现的问题，记录严重程度、复现步骤、负责人、修复方式和复测结果。
5. 补充至少 1 次测试交流或缺陷评审记录，说明问题如何分配和关闭。
6. 完成项目复盘，总结目标达成情况、成员贡献、主要收获、现存不足和后续计划。

## 提交内容

1. 一份测试收尾流程记录，建议文件名为 `03-测试收尾流程记录.md`。
2. 一份测试指南，建议文件名为 `docs/testing-guide.md`。
3. 测试用例及执行结果表。
4. 缺陷清单、修复记录和复测结果。
5. 内容校验结果、自动化测试结果和核心流程截图。
6. 至少 1 次测试交流或缺陷评审记录。
7. 项目总结以及每名成员不少于 300 字的个人反思。

## 测试用例必填字段

- 用例编号
- 测试功能
- 前置条件
- 操作步骤
- 预期结果
- 实际结果
- 测试结论
- 执行人及日期
- 对应版本或 Git 提交号

## 验收标准

- 核心测试用例字段完整，操作步骤可以复现。
- 严重缺陷已经修复；暂缓问题需注明原因、影响和规避方案。
- 内容配置校验达到 0 error；如存在 warning，需逐项说明。
- 修复后的问题有复测结果，形成完整闭环。
- 测试截图、日志和结果能够对应具体版本或提交。
- 至少包含 1 次真实测试交流或缺陷评审记录。
- 其他成员可以按照测试指南完成项目启动和核心流程验证。
- 文档内容真实，无账号、密钥等敏感信息。
