# 作业二：开发阶段——功能实现与协作过程归档

## 作业说明

项目主体功能已经完成。本作业不要求重复开发，而是根据现有代码、配置和 Git 记录，补齐开发阶段的实现、交流、联调和版本协作过程。

## 作业目标

还原项目从设计方案到可运行系统的实现过程，使其他成员能够了解各模块如何开发、如何协作，以及问题如何被发现和解决。

## 作业内容

1. 按前端、后端、Agent、内容配置四个模块概括已实现的核心功能。
2. 每名成员选择至少 1 个本人负责的代表性功能，记录：
   - 任务目标；
   - 实现步骤；
   - 关键文件；
   - 遇到的问题；
   - 解决方法；
   - 验证方式与结果。
3. 记录至少 1 次跨模块交流或联调过程，例如：前端发起操作，后端更新状态，Agent 生成叙事，前端展示结果。
4. 整理 Git 协作过程，包括分支、提交、合并请求、代码评审和冲突处理。
5. 说明开发过程中发生的需求、接口或实现方案变化，并记录沟通结果和影响范围。
6. 整理当前遗留问题，注明负责人、优先级和处理状态。

## 提交内容

1. 一份开发阶段流程记录，建议文件名为 `02-开发阶段流程记录.md`。
2. 每名成员至少 1 条有效 Git 提交或合并请求记录。
3. 至少 1 组核心功能运行截图、终端日志或接口响应。
4. 至少 1 次开发交流或联调记录，包含参与人、问题、结论和后续操作。
5. 关键代码与配置文件索引，注明文件路径和功能用途。
6. 遗留问题清单及当前处理状态。

## 流程记录建议结构

1. 开发目标与任务分工
2. 各模块完成情况
3. 个人代表性功能实现记录
4. 跨模块联调记录
5. Git 分支与合并流程
6. 问题及解决过程
7. 方案变更记录
8. 遗留问题与个人总结

## 验收标准

- 覆盖前端、后端、Agent、内容配置之间的真实协作关系。
- 每项代表性功能均能对应仓库中的代码、配置或文档。
- Git 记录与开发说明一致，提交信息清晰。
- 至少包含 1 次真实交流或联调过程，不能只提交最终效果截图。
- 问题记录包含现象、原因、处理方式和验证结果。
- 其他成员能够根据文档理解项目的核心调用链路。
- 文档内容真实，无账号、密钥等敏感信息。
